Section 03 – 04

PHP 8.3 & MariaDB 12.3 Setup

Installing PHP 8.3 Thread-Safe (VS17 x64)

1
Download PHP 8.3 TS VS17 x64 From windows.php.net/download — choose "Thread Safe" zip matching VS17 (Visual Studio 2022 build).
2
Extract to C:\xampp_moodle\php\ Replace old PHP folder contents. Keep the path identical — Apache config references this path.
3
Update httpd-xampp.conf LoadFile/LoadModule 
LoadFile "C:/xampp_moodle/php/php8ts.dll"
LoadFile "C:/xampp_moodle/php/libpq.dll"
LoadFile "C:/xampp_moodle/php/libsqlite3.dll"
LoadModule php_module "C:/xampp_moodle/php/php8apache2_4.dll"
4
Enable required extensions in php.ini 
extension_dir = "C:\xampp_moodle\php\ext"
extension=curl
extension=gd
extension=intl
extension=mbstring
extension=openssl
extension=soap
extension=sodium
extension=zip
max_input_vars = 5000
🚫 Do NOT add extra LoadFile for libcrypto/libssl
Attempting to LoadFile Apache's own OpenSSL DLLs alongside PHP's causes Apache to crash on startup. Only load the three DLLs listed above.

MariaDB 12.3 Upgrade

1
Stop MySQL service in XAMPP control panel Back up C:\xampp_moodle\mysql\data\ if needed.
2
Extract MariaDB 12.3 into C:\xampp_moodle\mysql\ Overwrite bin/, lib/, etc. — do NOT overwrite data/ yet.
3
Create C:\xampp_moodle\mysql\bin\my.ini 
[client]
port=3306
[mysqld]
port=3306
basedir="C:/xampp_moodle/mysql"
tmpdir="C:/xampp_moodle/tmp"
datadir="C:/xampp_moodle/mysql/data"
character-set-server=utf8mb4
collation-server=utf8mb4_unicode_ci
sql_mode=NO_ZERO_IN_DATE,NO_ZERO_DATE,NO_ENGINE_SUBSTITUTION
4
Initialize fresh data directory Clear data\ folder then run: 
C:\xampp_moodle\mysql\bin\mariadb-install-db.exe --datadir="C:\xampp_moodle\mysql\data"
5
Create the Moodle database Open phpMyAdmin → New → database name: moellim, collation: utf8mb4_unicode_ci.

Section 05 – 07

Apache Configuration Files

httpd.conf — Key Checks

No major changes required. Verify these two lines are present and uncommented:

LoadModule rewrite_module modules/mod_rewrite.so   # Required for .htaccess redirects

<Directory "C:/xampp_moodle/htdocs">
    AllowOverride All   # Required for .htaccess to work
    Require all granted
</Directory>

httpd-vhosts.conf — VirtualHost for Moellim

This routes http://moellim to Moodle's public/ subfolder, which is the Moodle 5.x web root.

<VirtualHost *:80>
    ServerName moellim
    DocumentRoot "C:/xampp_moodle/htdocs/moellim/public"
    <Directory "C:/xampp_moodle/htdocs/moellim/public">
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
💡 Why DocumentRoot points to /public
Moodle 5.x moved its web root into a public/ subfolder for security. The parent directory (moellim/) contains config.php and other server-only files that must never be web-accessible.

httpd-xampp.conf — Directory Security

Denies web access to the parent moellim/ directory, only allowing public/.

# Block access to parent Moodle directory
<Directory "C:/xampp_moodle/htdocs/moellim">
    AllowOverride All
    Require all denied
</Directory>

# Allow only the public web root
<Directory "C:/xampp_moodle/htdocs/moellim/public">
    Require all granted
    AllowOverride All
</Directory>

Windows Hosts File

Add this entry so http://moellim resolves locally:

File: C:\Windows\System32\drivers\etc\hosts

127.0.0.1    moellim
⚠ Run Notepad as Administrator
The hosts file requires admin rights to edit. Right-click Notepad → "Run as administrator", then open the file.

Moellim Root .htaccess

File: C:\xampp_moodle\htdocs\moellim\.htaccess — blocks all web access to the parent folder.

<IfModule mod_authz_core.c>
    Require all denied
</IfModule>

Section 08 – 11

Moodle 5.2 Installation

Moodle 5.x Architecture Change

Moodle 4.x (old)

Web root was the Moodle directory itself. DocumentRoot pointed directly to /moellim/.

Moodle 5.x (new) ✓

Web files moved to public/ subfolder. DocumentRoot must point to /moellim/public/.

Manual config.php Creation

The web installer can get stuck on the "Web server not configured" warning even when the server is correct. The fix is to bypass the installer by creating config.php manually.

File: C:\xampp_moodle\htdocs\moellim\config.php

<?php
unset($CFG);
global $CFG;
$CFG = new stdClass();

$CFG->dbtype    = 'mariadb';   // NOT 'mysqli' — must match driver name
$CFG->dblibrary = 'native';
$CFG->dbhost    = 'localhost';
$CFG->dbname    = 'moellim';
$CFG->dbuser    = 'root';
$CFG->dbpass    = '';
$CFG->prefix    = 'mdl_';
$CFG->dboptions = [
    'dbpersist'   => false,
    'dbport'      => '',
    'dbsocket'    => '',
    'dbcollation' => 'utf8mb4_unicode_ci',
];

$CFG->wwwroot = 'http://moellim';      // No /public — VirtualHost handles it
$CFG->dataroot  = 'C:\\moellimdata';   // Outside htdocs for security
$CFG->admin     = 'admin';
$CFG->directorypermissions = 02777;
$CFG->routerconfigured = false;

require_once(__DIR__ . '/lib/setup.php');
⛔ wwwroot must NOT end with /public
Even though DocumentRoot is /public, set $CFG->wwwroot = 'http://moellim' (no /public). Moodle throws a fatal error if wwwroot ends in /public.

Dataroot Directory

Create C:\moellimdata\ manually. It must be outside the web root (htdocs/) for security.

mkdir C:\moellimdata

Apache/PHP must have read/write access to this folder.

Completing the Install

After creating config.php, visit http://moellim/admin/index.php. Moodle will run database setup and create all tables. Accept all prompts.

Section 12 – 13

Custom Dashboard Plugin

Plugin Type: Local Plugin

A Moodle local plugin (local_*) is the correct type for a standalone custom page that doesn't fit into courses or blocks. It lives at public/local/ and has no UI constraints imposed by Moodle's block system.

FeatureBlock PluginLocal Plugin ✓ (used here)
Custom full-page layoutNoYes
External CSS frameworksStripped by purifierFull control
Access Moodle DB directlyYesYes
Redirect-able URLNoYes (via .htaccess)

File Structure

public/local/moellim_dashboard/ ├── version.php ← Plugin version & metadata ├── index.php ← Main dashboard page (PHP + HTML) └── lang/ └── en/ └── local_moellim_dashboard.php ← Language strings

version.php

<?php
defined('MOODLE_INTERNAL') || die();

$plugin->component = 'local_moellim_dashboard';
$plugin->version   = 2026062201;     // YYYYMMDDNN format
$plugin->requires  = 2024100700;     // Minimum Moodle version
$plugin->maturity  = MATURITY_STABLE;
$plugin->release   = '1.0';

lang/en/local_moellim_dashboard.php

<?php
defined('MOODLE_INTERNAL') || die();
$string['pluginname'] = 'Moellim Dashboard';

Plugin Installation

1
Place plugin files in public/local/moellim_dashboard/
2
Visit http://moellim/admin/index.php — Moodle detects the new plugin automatically.
3
Click "Upgrade Moodle database now" to register the plugin in the database.

PHP Data Layer & Frontend

PHP Data Queries (index.php top section)

<?php
require_once('../../config.php');
require_once($CFG->libdir . '/completionlib.php');  // Needed for completion_info class
require_login();

global $DB, $USER, $CFG, $PAGE, $OUTPUT;

$PAGE->set_url(new moodle_url('/local/moellim_dashboard/index.php'));
$PAGE->set_context(context_system::instance());
$PAGE->set_pagelayout('base');

// Live counts from Moodle database
$totalStudents = $DB->count_records('role_assignments', ['roleid' => 5]);  // roleid 5 = student
$totalTeachers = $DB->count_records('role_assignments', ['roleid' => 3]);  // roleid 3 = teacher
$totalCourses  = $DB->count_records('course') - 1;              // -1 to exclude site course
$totalSurveys  = $DB->count_records('feedback');

// User role detection
if (is_siteadmin()) {
    $userRole = 'admin';
} elseif ($DB->record_exists('role_assignments', ['userid' => $USER->id, 'roleid' => 3])) {
    $userRole = 'instructor';
}

// Enrolled courses for current user
$userCourses = enrol_get_my_courses();

// Pass all data to JavaScript as JSON
$jsData = json_encode([
    'stats'   => ['students' => $totalStudents, ...],
    'user'    => ['name' => fullname($USER), 'role' => $userRole],
    'courses' => $coursesData,
    'siteurl' => $CFG->wwwroot,
]);

Frontend Stack

The dashboard uses a CDN-loaded frontend stack — no build tools or npm required:

💡 Why Tailwind via CDN, not Moodle's theme CSS?
Moodle's HTML purifier strips inline styles and many class names from Text/HTML blocks. Using a local plugin page bypasses the purifier entirely — the page renders raw HTML with full Tailwind support.

Tailwind Brand Colors Override

Tailwind's default brand color is overridden to Riphah University green (#00703C):

tailwind.config = {
    theme: {
        extend: {
            colors: {
                brand: {
                    50:  '#f0fdf4',
                    600: '#00703C',   // Riphah green
                    700: '#15803d',
                }
            }
        }
    }
}

Section 16

Default Dashboard Redirect

Making the Custom Dashboard the Default

When a user logs into Moodle, they are sent to /my/ (Moodle's default dashboard). We redirect that to our custom plugin page using .htaccess.

File: C:\xampp_moodle\htdocs\moellim\public\.htaccess

Options -Indexes

RewriteEngine On

# Redirect Moodle default dashboard to custom dashboard
RewriteRule ^my/$  /local/moellim_dashboard/index.php [R=302,L]
RewriteRule ^my$   /local/moellim_dashboard/index.php [R=302,L]

Prerequisites for Redirect to Work

✓ mod_rewrite loaded
LoadModule rewrite_module modules/mod_rewrite.so must be uncommented in httpd.conf.
✓ AllowOverride All
The Directory block for htdocs must have AllowOverride All so .htaccess is processed.

Section 19

QEC Surveys Roadmap

The dashboard is built and working. The next phase is setting up Quality Enhancement Cell (QEC) surveys using Moodle's built-in Feedback module.

1
Create Departments as Course Categories Site Admin → Courses → Manage categories → Add categories (e.g. Faculty of Computing, Faculty of Engineering).
2
Create Courses per Department Each course represents a subject. Add teachers and enroll students.
3
Create QEC Feedback Activity Inside a course → Turn editing on → Add activity → Feedback. Design questions (rating scales, text, multiple choice).
4
View Responses & Analysis Feedback module provides built-in charts and export to Excel/CSV. Responses are anonymous by default.
5
Connect to Dashboard Update the QEC Surveys tab in local/moellim_dashboard/index.php to list active feedbacks from mdl_feedback table and link to their response pages.
✓ Dashboard Survey Count
The "QEC Surveys" stat card on the dashboard already queries SELECT COUNT(*) FROM mdl_feedback live — it will automatically update as you create more surveys.
